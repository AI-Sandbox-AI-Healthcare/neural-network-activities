Why Use a Taxonomy?
Cross-entropy is hierarchy-blind
Standard loss treats confusing leopard with cheetah the same as confusing leopard with chair. But these are not equally wrong!
Hierarchy = similarity

Stage 4 — Several Channels: Where One A Breaks

Real conv layers have several input channels c and output channels o. A conv layer has a separate 3×3 pattern for every pair (o, c).

In h′ = W·h·A, the matrix W only mixes channels and A only mixes pixels, so output channel o gets

h′[o] = Σc W[o][c] · (h[c] · A)

Every pair (o, c) therefore uses the same spatial pattern A, just scaled by the number W[o][c].

The general fix

Use nine 0/1 adjacency matrices Ak, one per neighbour position k ("Aup-left[j][i] = 1 if j is i's up-left neighbour"), each with its own learned channel-mixing matrix Wk:

h′ = f( Σk Wk · h · Ak + b )

Now every (o, c, position) has its own weight Wk[o][c] — exactly a conv layer. Graph models that give different edge types their own weights (relational GCNs) use the same idea.

Stage 5 — The Flip Side: Real Graphs

On images, "one W for every neighbour" is a limitation. But molecules and social networks have no "up" or "left", and one node may have 3 neighbours while another has 300.

Takeaway — the full answer
  • With the usual 0/1 A* and one W: no. A* says which pixels are neighbours but not where they sit, so every neighbour gets the same weight — only an all-equal kernel (a blur) is possible.
  • With a weighted A: yes, for one channel. Put the kernel weight for each neighbour position into A and set W = 1. But then A is the kernel copied in by hand, directed (up-left ≠ down-right), and tied to the pixel grid.
  • With several channels, one A is not enough: every channel pair shares A's pattern. One Ak and Wk per position, h′ = f(Σk Wk·h·Ak + b), recovers a full conv layer.
  • On real graphs neighbours have no positions, so GCN's shared, order-free rule is exactly right: reorder the nodes and the outputs are reordered the same way (permutation equivariance).

Random search trains every configuration to the end, even hopeless ones. Successive halving trains many configurations briefly and keeps only the best. from math import log, ceil
max_iter = 1000   # iterations for a fully trained configuration
eta = 10          # keep the best 1/eta at every rung
logeta = lambda x: log(x) / log(eta)
s_max = int(logeta(max_iter))
B = (s_max + 1) * max_iter

for s in reversed(range(s_max + 1)):                       # one bracket per s
    n = int(ceil(int(B / max_iter / (s + 1)) * eta ** s))   # configurations to start
    r = max_iter * eta ** (-s)                              # iterations each, first rung
    T = [random_hyperparameters() for i in range(n)]
    for i in range(s + 1):                                  # successive halving
        n_i = n * eta ** (-i)
        r_i = r * eta ** i
        losses = [run_then_return_val_loss(r_i, t) for t in T]
        T = [T[j] for j in argsort(losses)[:int(n_i / eta)]]

Takeaway
  • Saliency is the slope at the input. When the output is saturated, it gives 0 even to words the prediction depends on.
  • Occlusion deletes one word at a time. When two words carry redundant evidence, each one looks unimportant on its own (0.2 here).
  • Shapley values average a word's contribution over every order of adding the words and always add up to f(x) − f(blank). Interactions get split: φbad = 0, although "bad" changes the score by ±0.4. The exact values need 2n model evaluations, so KernelSHAP samples them.
  • Integrated gradients collect the slope along a path from a blank input, so they also add up to the total (0.5 + 0.5 = 1).
  • Trust needs tests: an explanation that does not change when the weights are randomized ignores the model (Adebayo et al., 2018). The best use of explanations is catching models that are right for the wrong reason, like snow meaning "wolf".
