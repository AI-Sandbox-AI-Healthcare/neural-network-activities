Why Computational Graphs?
Step 1 of 4
⚡ No Redundant Computation
p appears in 4 equations but is computed once. The graph caches the result and fans it out to 4 consumers — no wasted work.
∂ Automatic Differentiation
A gradient shows how much the output changes when an input changes. Walk backward from the output, edge by edge, adding gradients wherever a node like p feeds multiple paths.
🗺 Execution Blueprint
A node can't run until its inputs are ready, so the graph order matters: compute inputs first, then work forward node by node — exactly what PyTorch does at runtime.

Step 3 of 3 — The Shared Variable Insight
In the equations
pappears on RHS of all 4 equations
zappears in equation 4 twice: (1−z) and z⊙n
rappears in equation 3
In the graph
p1 node, 4 outgoing edges (shared)
z1 node, 2 outgoing edges to y
r1 node, 1 outgoing edge to n
  • Every variable appears exactly once as a node, no matter how many equations reference it.
  • Multiple outgoing edges = the value is reused, not recomputed.
  • This is why PyTorch's autograd can accumulate ∂L/∂p from all 4 paths in one backward pass.
