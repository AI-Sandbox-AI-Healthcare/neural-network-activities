Stage 4 — Several Channels: Where One A Breaks

Real conv layers have several input channels c and output channels o. A conv layer has a separate 3×3 pattern for every pair (o, c).

In h′ = W·h·A, the matrix W only mixes channels and A only mixes pixels, so output channel o gets

h′[o] = Σc W[o][c] · (h[c] · A)

Every pair (o, c) therefore uses the same spatial pattern A, just scaled by the number W[o][c].

The general fix

Use nine 0/1 adjacency matrices Ak, one per neighbour position k ("Aup-left[j][i] = 1 if j is i's up-left neighbour"), each with its own learned channel-mixing matrix Wk:

h′ = f( Σk Wk · h · Ak + b )

Now every (o, c, position) has its own weight Wk[o][c] — exactly a conv layer. Graph models that give different edge types their own weights (relational GCNs) use the same idea.

Stage 5 — The Flip Side: Real Graphs

On images, "one W for every neighbour" is a limitation. But molecules and social networks have no "up" or "left", and one node may have 3 neighbours while another has 300.

Takeaway — the full answer
  • With the usual 0/1 A* and one W: no. A* says which pixels are neighbours but not where they sit, so every neighbour gets the same weight — only an all-equal kernel (a blur) is possible.
  • With a weighted A: yes, for one channel. Put the kernel weight for each neighbour position into A and set W = 1. But then A is the kernel copied in by hand, directed (up-left ≠ down-right), and tied to the pixel grid.
  • With several channels, one A is not enough: every channel pair shares A's pattern. One Ak and Wk per position, h′ = f(Σk Wk·h·Ak + b), recovers a full conv layer.
  • On real graphs neighbours have no positions, so GCN's shared, order-free rule is exactly right: reorder the nodes and the outputs are reordered the same way (permutation equivariance).
