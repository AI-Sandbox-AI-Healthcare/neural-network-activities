Activity 10.4Named Entity Recognition — Tagging vs. Sequence-to-Sequence✓ 10.4 Completed

Named entity recognition (NER) finds the people, places and organisations in a sentence. The classic model is a tagger: it reads the sentence and gives every word one label. A sequence-to-sequence (encoder–decoder) model instead reads the sentence and writes its answer one token at a time, at whatever length the answer needs.

Q1 What does each model output, and how long is the output?
Q2 What can a written answer express that one label per word cannot?
Q3 What does writing the answer cost?

Why these questions: they compare the two ways to frame NER: labelling every word, or writing the answer out.

  • Q1 → Stages 1–2: tag a sentence yourself, then count the tokens of three answer formats.
  • Q2 → Stage 3: try to tag an entity that sits inside another.
  • Q3 → Stage 4: count decoder steps and see what a decoder can get wrong.
Stage 1 — Be the Tagger

Taggers use BIO labels: B-TYPE marks the first word of an entity, I-TYPE each following word of the same entity, and O a word outside every entity. Label each word.

Types: PER (person), ORG (organisation), LOC (location).

Takeaway
  • A tagger outputs one label per word, so the output length always equals the input length. It labels every word in one parallel pass, but each label is chosen separately, so invalid sequences (I- after O) need a CRF layer or constrained decoding.
  • A seq2seq model writes its answer (Goodfellow §10.4): the encoder reads the sentence into a context C, and the decoder writes token after token until <END>. The length is free: for n words with e entities covering m words, inline markup writes n + 2e tokens and an entity list e + m.
  • What writing gains: nested entities (University of Arizona) and any output format you can train on. One label per word cannot hold two entities.
  • What it costs: one sequential step per output token, possible hallucinated or malformed output, and (for lists) lost positions when a word repeats.
