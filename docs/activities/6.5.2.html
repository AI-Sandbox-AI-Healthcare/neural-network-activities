Algorithm
build_grad(V, G, G′, grad_table):
  if V ∈ grad_table: return grad_table[V]
  for i, C ∈ enumerate(get_consumers(V, G′)):
    op ← get_operation(C)
    D ← build_grad(C, G, G′, grad_table)
    G(i) ← op.bprop(get_inputs(C,G′), V, D)
  return G = grad_table[V] = Σᵢ G(i)

Why build_grad?
Step 1 of 3
⚡ One backward pass
Computing all gradients ∂L/∂uⁱ at once is no more expensive than a single forward pass — O(edges) total work.
🔁 Recursive + cached
grad_table memoises each G so shared nodes (like p in 6.5.1) accumulate contributions from all consumers without redundant calls.
∂ Chain rule formalised
Each op.bprop multiplies the upstream gradient D by the local derivative dC/dV — this is the chain rule encoded as data.

What You Just Did
  • build_grad starts at the output (G=1) and multiplies local derivatives backward.
  • For addition: local derivative = 1 for both inputs — gradients pass through unchanged.
  • For multiplication u¹×u²: d/du¹ = u² = 5 — the other operand becomes the gradient multiplier.
  • For abs(u⁵): d/du⁵ = sign(u⁵) = −1 (since u⁵ = −2 < 0).
  • The final G(u¹) = −5 means decreasing u¹ by ε increases u⁶ by 5ε — gradient descent would raise u¹.
